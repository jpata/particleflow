# Paired CLD ECAL and HCAL granularity scans

Two independent six-point scans use the pinned 2025-05-29 Key4hep release and
`CLD_o2_v07` geometry. Each point runs 10,000 events as 100 jobs of 100 events.
Simulation and reconstruction use the same point-specific compact XML. Only
reconstructed EDM4hep ROOT is retained; its simulated and digitized calorimeter
hit collections remain available for analysis.

| Scan | Pitches | Process | Common seeds |
| --- | --- | --- | --- |
| ECAL | 5.1, 4, 3, 2.5, 2, 1.5 mm | `p8_ee_Z_tautau_ecm91` | 700000–700099 |
| HCAL | 30, 25, 20, 15, 12, 10 mm | `p8_ee_ttbar_ecm365` | 300000–300099 |

ECAL barrel and endcap share each ECAL pitch; HCAL remains at 30 mm. HCAL
barrel and endcap share each HCAL pitch; ECAL remains at 5.1 mm. All ECAL
points, **including 5.1 mm**, have an ECAL-silicon-only 1 mm maximum Geant
step. HCAL and other calorimeter sensitive layers retain the 5 mm default.
This means the scan's 5.1 mm ECAL arm is a new baseline and cannot simply be
replaced by older 5.1 mm output. The HCAL 30 mm geometry is an exact copy of
the pinned baseline.

The ECAL generator card is a copy of the existing Z→ττ card with the 91 GeV
beam spot values used by CLD reconstruction. The runner passes `--cms 91` to
reconstruction for ECAL points and `--cms 365` for HCAL points. Generation
uses identical cards and seed ranges across points; compare generator records
before treating corresponding files as exact pairs.

Geometry variants and `manifest.json` files are generated by
`prepare_granularity_scan.py` from the pinned k4geo release. Re-running the
script verifies existing files rather than overwriting differences. The
manifests record the source directory and its SHA-256 digest.

## Production and TFDS conversion

Each point is a `particleflow_spec.yaml` production named
`cld_ecal_pitch_<pitch>` or `cld_hcal_pitch_<pitch>`, where the decimal point is
written as `p` (for example `cld_ecal_pitch_2p5`). Outputs live under
`/local/joosep/mlpf/cld/granularity_scan_2025-05-29/<subsystem>_<pitch>mm/`.

All 1,200 ROOT files were generated in October 2026. The productions now set
`dataset_only: true`, which creates postprocessing, cluster/track TFDS, and
hit-level TFDS rules without rerunning simulation or starting training. The
existing CLD postprocessor uses `--detector cld`. Each point writes Parquet
under `post/<process>/` and TFDS datasets under `tfds/` in its own workspace.
The τ sample uses new Z→ττ builders; the ttbar scan reuses the existing CLD
ttbar builders. Each view has 10 numbered TFDS configs, with the same
seed-sorted 90/10 train/test partition at every pitch.

Use the Tallinn Pixi environment. Preview the postprocessing for one point:

```bash
PROD=cld_ecal_pitch_5p1 pixi run post --dry-run --printshellcmds
```

Launch all 12 points as a Slurm array (two point controllers active at once):

```bash
sbatch scripts/cld_ecal_readout/build_granularity_tfds.sbatch
```

The controller runs the three steps sequentially for each point. A failed
step stops that point; rerunning skips completed outputs. To run one point
manually:

```bash
PROD=cld_ecal_pitch_5p1 pixi run post --jobs 20
PROD=cld_ecal_pitch_5p1 pixi run tfds --jobs 5
PROD=cld_ecal_pitch_5p1 pixi run tfds_hit --jobs 3
```

The original ROOT-generation helper and controller are retained in
`launch_granularity_scan.sh` and `scan_driver.sbatch` as a record of the
simulation setup. Dataset conversion keeps PF and hit outputs separate and
uses point-specific scratch directories to avoid collisions across scan jobs.

## Evaluation

For ECAL, use τ decays with truth π⁰→γγ. Plot resolved two-photon efficiency
versus truth opening angle and photon energy, as well as fake/split photon
fraction, photon energy response and τ visible-energy response. Separate
converted photons and events where one daughter is outside ECAL acceptance.

For HCAL, compare neutral-hadron efficiency and response, charged-to-neutral
confusion and the Pandora PF jet response and resolution. Retain per-event
pairing and plot performance against truth neutral-hadron energy fraction.
Record hit occupancy, file size, runtime and peak memory at every pitch.

First compare all points using the unchanged digitization and Pandora
configuration to expose sensitivity to the raw detector change. A second
comparison after per-point calibration is needed before ranking intrinsic
detector designs.
